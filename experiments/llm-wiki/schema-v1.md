## Назначение
Эта вики — структурированная база знаний с перекрёстными ссылками для командного чата.
Claude ведёт вики. Человек подбирает источники, задаёт вопросы и направляет анализ.

## Структура папок
```
raw/          -- исходные документы (неизменяемые -- никогда их не редактировать)
wiki/         -- markdown-страницы, которые ведёт Claude
wiki/index.md -- оглавление всей вики
wiki/log.md   -- журнал всех операций, только дописывание в конец
```

## Приём нового источника
Когда пользователь кладёт новый источник в `raw/` и просит его обработать:
1. Прочитать исходный документ целиком
2. Обсудить с пользователем ключевые выводы, прежде чем что-либо записывать
3. Создать в `wiki/` страницу с кратким изложением, названную по имени источника
4. Создать или обновить страницы понятий для каждой значимой идеи или сущности
5. Расставить вики-ссылки ([[имя-страницы]]), связывающие смежные страницы
6. Обновить `wiki/index.md`: добавить новые страницы с однострочными описаниями
7. Дописать в `wiki/log.md` запись с датой, названием источника и описанием изменений

Один источник может затронуть 10–15 страниц вики. Это нормально.

## Формат страницы
Каждая страница вики должна иметь такую структуру:
```markdown
# Заголовок страницы
**Краткое описание**: одно-два предложения о том, чему посвящена страница.
**Источники**: список файлов из raw/, на которые опирается страница.
**Обновлено**: дата последнего изменения.
---
Здесь основной текст. Использовать понятные заголовки и короткие абзацы.
По ходу текста связывать смежные понятия через [[вики-ссылки]].

## Связанные страницы
- [[смежное-понятие-1]]
- [[смежное-понятие-2]]
```

## Правила цитирования
- Каждое фактическое утверждение должно ссылаться на файл-источник
- Использовать формат (источник: filename.pdf) сразу после утверждения
- Если два источника противоречат друг другу, явно зафиксировать противоречие
- Если у утверждения нет источника, пометить его как требующее проверки

## Ответы на вопросы
Когда пользователь задаёт вопрос:
1. Сначала прочитать `wiki/index.md`, чтобы найти подходящие страницы
2. Прочитать эти страницы и на их основе составить ответ
3. Сослаться в ответе на конкретные страницы вики
4. Если ответа в вики нет, прямо об этом сказать
5. Если ответ ценный, предложить сохранить его как новую страницу вики

Удачные ответы стоит возвращать в вики, чтобы знание накапливалось.

## Проверка вики (lint)
Когда пользователь просит проверить вики или провести аудит:
- Искать противоречия между страницами
- Находить страницы-сироты (на которые нет входящих ссылок)
- Выявлять понятия, упомянутые на страницах, но не имеющие собственной страницы
- Отмечать утверждения, которые могли устареть в свете более новых источников
- Проверять, что все страницы соответствуют формату выше
- Оформить результаты нумерованным списком с предложениями по исправлению

## Правила
- Никогда ничего не менять в папке `raw/`
- После любых изменений всегда обновлять `wiki/index.md` и `wiki/log.md`
- Имена страниц — строчными латинскими буквами через дефис (например, `machine-learning.md`)
- Писать ясным, простым языком
- Если непонятно, куда что отнести, спросить пользователя
