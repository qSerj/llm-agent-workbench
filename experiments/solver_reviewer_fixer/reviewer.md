# Проверка фактической корректности документации

Проверь `docs/01-interleavers.md` строго по файлам в `src/**`. Не доверяй
правдоподобию и не используй знания вне репозитория. Проверь каждое утверждение
о публичном интерфейсе, реализациях, ограничениях, кодировании, назначении
значений, передаче данных и примере использования.

Не изменяй исходный документ. Создай только `docs/review-findings.json` в виде
JSON без комментариев:

```json
{
  "verdict": "PASS или FAIL",
  "findings": [
    {
      "id": "короткий-стабильный-идентификатор",
      "claim": "проверяемое утверждение документа",
      "status": "SUPPORTED, CONTRADICTED или UNKNOWN",
      "evidence": ["путь:строка и краткий подтверждающий факт"],
      "suggested_fix": "конкретное исправление либо пустая строка"
    }
  ]
}
```

В `findings` включай только `CONTRADICTED` и `UNKNOWN`; подтверждённые
утверждения перечислять не нужно. `PASS` допустим только при пустом списке.
`UNKNOWN` означает, что репозиторий не подтверждает утверждение, даже если оно
может быть верным в реальной системе. Перед завершением перечитай спорные
исходные файлы.
