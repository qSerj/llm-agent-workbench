# Строгая проверка фактической корректности документации

Проверь `docs/01-interleavers.md` строго по файлам в `src/**`. Не изменяй
исходный документ. Создай только `docs/review-findings.json` в том же формате,
который описан ниже.

Правила доказательства:

1. Имя типа, метода, параметра или переменной не доказывает реальный аппаратный
   смысл и физическое назначение значения.
2. Вызов транспортного интерфейса доказывает только вызов этого интерфейса, но
   не доставку данных устройству и не поведение оборудования.
3. Утверждение о том, как устройство интерпретирует длину массива, индекс или
   число, считается `UNKNOWN`, если это явно не написано или не проверяется в
   репозитории.
4. Каждая ссылка `путь:строка` должна указывать на существующую строку, которая
   непосредственно подтверждает соседнее утверждение.
5. Правдоподобное, но не доказанное утверждение получает `UNKNOWN`, а не
   `SUPPORTED`.

Формат результата — JSON без комментариев:

```json
{
  "verdict": "PASS или FAIL",
  "findings": [
    {
      "id": "короткий-стабильный-идентификатор",
      "claim": "проверяемое утверждение документа",
      "status": "CONTRADICTED или UNKNOWN",
      "evidence": ["путь:строка и краткий подтверждающий факт"],
      "suggested_fix": "конкретное исправление"
    }
  ]
}
```

`PASS` допустим только при пустом списке замечаний. Перед завершением перечитай
каждый исходный файл, на который ссылается документ.
