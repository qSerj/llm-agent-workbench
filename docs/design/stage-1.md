# Описание эксперимента

Статус: реализовано. Дата: 2026-08-16.

Заменяет каталог `docs/design/stage-1/` (678 строк проектирования, 48 открытых
вопросов, ноль файлов формата). Прежние черновики остаются в истории Git.
Здесь описано то, что действительно работает, а не то, что предполагалось.

## Что это

Один файл описывает эксперимент до запуска. `tools/run_chain.py` читает его,
исполняет каждый способ решения по этапам и пишет по карточке исполнения на
способ. Карточка — существующий `schemas/execution-envelope-v1.schema.json`,
она не менялась.

Эксперимент живёт каталогом: описание, промпты ролей и рабочее пространство
лежат рядом, а не разбросаны по репозиторию.

```
experiments/solver-reviewer-fixer/
  experiment.yaml    намерение до запуска
  task.md            формулировка задачи
  reviewer.md        промпты ролей
  reviewer-v2.md
  fixer.md
  workspace/         вход, который получает первый этап
```

```
experiments/*/experiment.yaml   намерение до запуска
        ↓  tools/run_chain.py
execution-envelope.json   факт после запуска
        ↓  ui/
сравнение способов с разбивкой затрат по этапам
```

Результат прогона складывается по дню, когда он случился:

```
executions/<эксперимент>/<дата>/<способ>-r<повтор>/
```

Повтор в тот же день получает суффикс `-2`, `-3`. Исполнитель отказывается
писать поверх существующего каталога, поэтому прежний результат нельзя потерять
случайно. Прогоны, записанные до появления даты, лежат на уровень выше;
оболочка показывает и их.

## Формат

```yaml
id: solver-reviewer-fixer-task01
question: Устраняет ли цепочка фактические ошибки лучше одиночного исполнителя?
workspace: experiments/solver-reviewer-fixer/workspace
task: task-01-repository-discovery      # необязательно, по умолчанию — id
case: interleaver-fixture               # необязательно, по умолчанию — имя каталога
repetitions: 1                          # необязательно
evaluate:
  citations: docs/01-interleavers.md
  suite:                                  # скрытый набор проверок
    path: experiments/wrap-defect/checks  # рядом с промптами, ВНЕ workspace
    command: [python3, run_checks.py]
    timeout: 120
candidates:
  - id: chain-v2
    stages:
      - role: SOLVER
        model: xiaomi/mimo-v2.5
        prompt: experiments/solver-reviewer-fixer/task.md
        allow_edit: [docs/01-interleavers.md]
```

Верхний уровень: `id`, `question`, `workspace`, `candidates` — обязательны;
`task`, `case`, `repetitions`, `evaluate` — необязательны. Этап: `role`,
`model`, `prompt`, `allow_edit`; `allow_bash`, `provider`, `base_url`,
`api_key_env` — необязательны. Роли: `SOLVER`, `REVIEWER`, `FIXER`, `OTHER`.

`allow_bash` перечисляет команды, которые этапу разрешено запускать:

```yaml
      - role: REVIEWER
        model: deepseek/deepseek-v4-flash
        prompt: experiments/wrap-defect/reviewer.md
        allow_edit: [review-findings.json]
        allow_bash: [python3*]
```

Не объявлено — действует набор исполнителя по умолчанию (`git status*`,
`git diff*`, `dotnet build*`, `dotnet test*`), сложившийся, пока материал был
только на C#. Объявленный список **заменяет** его целиком, а не дополняет:
перечень должен читаться как полный ответ на вопрос «что этот этап запускает».
Пустой список — тоже ответ: этап не запускает ничего. `*` отклоняется — это не
объявление. Всё остальное по-прежнему `deny`, включая сеть.

Описание заводится и правится из оболочки: `/experiment/{name}` показывает его
матрицей «способ × этап» вместе с промптами, `/experiment/new` создаёт новое.
Запись детерминирована — порядок полей, свёрнутый вопрос и ведущий комментарий
сохраняются, — а черновик проверяется до записи теми же правилами, что применяет
исполнитель ([ADR 0007](../decisions/0007-planning-experiments-in-the-shell.md)).
Заготовку нового описания может предложить модель
([ADR 0008](../decisions/0008-drafting-an-experiment-with-a-model.md)); поле
`model` она оставляет пустым намеренно.

## Решения, которые держатся

1. **Намерение и факт разделены.** YAML описывает план, карточка — случившееся.
2. **Этап правит только объявленные файлы.** `allow_edit` — точные относительные
   пути; шаблоны и выход за пределы рабочего пространства отклоняются до запуска.
   Это обеспечивает программа, а не договорённость в документации.
3. **Никакой оболочки.** Аргументы передаются процессу списком; строка оболочки,
   `&&`, перенаправления и подстановка команд не поддерживаются.
   Что этап вправе запускать внутри песочницы — свойство эксперимента
   (`allow_bash`), а не исполнителя: проверяющему, которому нечем запустить код,
   остаётся только рассуждать о нём.
4. **Человеческий вопрос обязателен.** `question` хранится рядом с матрицей,
   чтобы техническая часть не вытеснила смысл исследования.
5. **Варианты явные и именованные.** Автоматического перебора параметров нет:
   каждый способ перечислен, у каждого есть имя.
6. **Ссылки версионированы.** `task` и `case` — идентификатор плюс версия.
7. **Повторения явные**, по умолчанию одно.
8. **Правила оценки отделены от способов.** `evaluate` описывает проверку
   результата и не зависит от того, кто его получил. Отделены и от рабочего
   пространства: скрытый набор проверок лежит вне него и накладывается на копию
   после прогона, поэтому исполнитель не может под него подстроиться
   ([ADR 0009](../decisions/0009-hidden-check-suite.md)). Путь набора внутри
   `workspace` отклоняется при чтении описания.
9. **Неизвестное остаётся неизвестным.** Провайдер не сообщил цену — измерение
   `null`, а не ноль. Если цена неизвестна хотя бы для одного этапа, итог по
   способу тоже неизвестен: частичная сумма занизила бы стоимость.
10. **Универсального балла нет.** Время, деньги, вызовы и вердикты остаются
    раздельными; вердикт не выводится из числа.
11. **Цепочка — последовательность.** Порядок этапов задаёт `depends_on`,
    рабочее пространство этапа N+1 — это выход этапа N.

## Чего намеренно нет

Пяти отдельных документов (`task.yaml`, `case.yaml`, `candidate.yaml`,
`evaluation.yaml`, `experiment.yaml`) — один файл виден целиком и этого пока
хватает. Внешних `uri` для входов. Графа этапов сложнее цепочки. Расписаний и
очередей. Автоматического подбора цепочки. Единой числовой оценки.

Поле добавляется, когда в него упёрся настоящий прогон.

## Как проверялось

`tests/test_chain.py`, `tests/test_experiment.py`, `tests/test_citations.py` —
сборка карточки со связанными этапами, распределение измерений по этапам,
отклонение обхода путей и шаблонов в `allow_edit`, неизвестная стоимость,
разбор описания. Контрольный пример:
`experiments/solver-reviewer-fixer/experiment.yaml`.
