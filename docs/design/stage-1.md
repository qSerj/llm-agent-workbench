# Описание эксперимента

Статус: реализовано. Дата: 2026-08-16.

Заменяет каталог `docs/design/stage-1/` (678 строк проектирования, 48 открытых
вопросов, ноль файлов формата). Прежние черновики остаются в истории Git.
Здесь описано то, что действительно работает, а не то, что предполагалось.

## Что это

Один файл описывает эксперимент до запуска. `tools/run_chain.py` читает его,
исполняет каждый способ решения по этапам и пишет по карточке исполнения на
способ. Карточка — существующий `schemas/execution-envelope-v1.schema.json`,
она не менялась.

```
experiments/*.yaml   намерение до запуска
        ↓  tools/run_chain.py
execution-envelope.json   факт после запуска
        ↓  ui/
сравнение способов с разбивкой затрат по этапам
```

## Формат

```yaml
id: solver-reviewer-fixer-task01
question: Устраняет ли цепочка фактические ошибки лучше одиночного исполнителя?
workspace: archive/prototype-r4.2/fixture
task: task-01-repository-discovery      # необязательно, по умолчанию — id
case: interleaver-fixture               # необязательно, по умолчанию — имя каталога
repetitions: 1                          # необязательно
evaluate:
  citations: docs/01-interleavers.md
candidates:
  - id: chain-v2
    stages:
      - role: SOLVER
        model: xiaomi/mimo-v2.5
        prompt: archive/prototype-r4.2/tasks/01.md
        allow_edit: [docs/01-interleavers.md]
```

Верхний уровень: `id`, `question`, `workspace`, `candidates` — обязательны;
`task`, `case`, `repetitions`, `evaluate` — необязательны. Этап: `role`,
`model`, `prompt`, `allow_edit`; `provider`, `base_url`, `api_key_env` —
необязательны. Роли: `SOLVER`, `REVIEWER`, `FIXER`, `OTHER`.

## Решения, которые держатся

1. **Намерение и факт разделены.** YAML описывает план, карточка — случившееся.
2. **Этап правит только объявленные файлы.** `allow_edit` — точные относительные
   пути; шаблоны и выход за пределы рабочего пространства отклоняются до запуска.
   Это обеспечивает программа, а не договорённость в документации.
3. **Никакой оболочки.** Аргументы передаются процессу списком; строка оболочки,
   `&&`, перенаправления и подстановка команд не поддерживаются.
4. **Человеческий вопрос обязателен.** `question` хранится рядом с матрицей,
   чтобы техническая часть не вытеснила смысл исследования.
5. **Варианты явные и именованные.** Автоматического перебора параметров нет:
   каждый способ перечислен, у каждого есть имя.
6. **Ссылки версионированы.** `task` и `case` — идентификатор плюс версия.
7. **Повторения явные**, по умолчанию одно.
8. **Правила оценки отделены от способов.** `evaluate` описывает проверку
   результата и не зависит от того, кто его получил.
9. **Неизвестное остаётся неизвестным.** Провайдер не сообщил цену — измерение
   `null`, а не ноль. Если цена неизвестна хотя бы для одного этапа, итог по
   способу тоже неизвестен: частичная сумма занизила бы стоимость.
10. **Универсального балла нет.** Время, деньги, вызовы и вердикты остаются
    раздельными; вердикт не выводится из числа.
11. **Цепочка — последовательность.** Порядок этапов задаёт `depends_on`,
    рабочее пространство этапа N+1 — это выход этапа N.

## Чего намеренно нет

Пяти отдельных документов (`task.yaml`, `case.yaml`, `candidate.yaml`,
`evaluation.yaml`, `experiment.yaml`) — один файл виден целиком и этого пока
хватает. Внешних `uri` для входов. Графа этапов сложнее цепочки. Расписаний и
очередей. Автоматического подбора цепочки. Единой числовой оценки.

Поле добавляется, когда в него упёрся настоящий прогон.

## Как проверялось

`tests/test_chain.py`, `tests/test_experiment.py`, `tests/test_citations.py` —
сборка карточки со связанными этапами, распределение измерений по этапам,
отклонение обхода путей и шаблонов в `allow_edit`, неизвестная стоимость,
разбор описания. Контрольный пример: `experiments/solver-reviewer-fixer.yaml`.
