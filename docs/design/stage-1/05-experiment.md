# Спецификация эксперимента

Статус: начальный черновик; два решения согласованы.

## Назначение

Эксперимент выбирает уже описанные задачу, примеры, способы решения и правила
оценки. Он отвечает на человеческий исследовательский вопрос и создаёт матрицу
отдельных исполнений.

Пример представления в будущей оболочке:

```text
Название: Проверка преобразования звука

Вопрос:
Какой способ правильно преобразует разные виды звука без слышимых
дефектов и с меньшими затратами?

Примеры:
1. Короткая музыкальная запись
2. Запись речи
3. Запись с участками тишины

Способы решения:
1. ffmpeg с параметрами A
2. ffmpeg с параметрами B

Повторения: по одному разу
Итого: 3 × 2 × 1 = 6 исполнений
```

## Согласованные решения

1. Эксперимент обязательно сохраняет человеческий вопрос `question`: что именно
   мы хотим выяснить. Техническая матрица не должна вытеснять смысл исследования.
2. В версии 0.1 варианты способа решения перечисляются явно и получают понятные
   имена. Автоматического перемножения списков параметров пока нет.

Например, два значения `temperature` представляются двумя видимыми вариантами,
а не скрытым перебором:

```text
MiMo, temperature 0.2
MiMo, temperature 0.8
```

Способ решения должен заранее объявить, какие параметры эксперимент вправе
менять. Замена неразрешённого поля считается другим способом решения или новой
его версией.

## Пока не решено

- окончательный состав и синтаксис `experiment.yaml`;
- замена и дополнение правил оценки;
- ограничения времени и общего бюджета;
- предварительная проверка матрицы до запуска;
- вычисляемый идентификатор фактической конфигурации;
- правило обобщения результатов по примерам и повторениям.

Следующее обсуждение начнётся с этого человеческого макета, а не с перечня полей
YAML. Код формата пока не пишется.
