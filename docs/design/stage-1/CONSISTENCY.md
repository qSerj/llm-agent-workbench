# Ревизия согласованности

Дата ревизии: 2026-08-13. Статус: исходная ревизия пройдена.

## Проверенные границы

| Вопрос | Решение | Согласованность |
| --- | --- | --- |
| Задача и способ решения | Задача не содержит алгоритм или модель | Согласовано с `VISION.md` |
| Задача и пример | Задача объявляет места входа; пример связывает конкретные данные | Не противоречит карточке исполнения |
| Задача и оценивание | Есть правило по умолчанию; эксперимент может заменить или дополнить | Согласовано в обсуждении |
| Открытые и закрытые данные | Исполнитель видит `case.yaml` и входы; эталон изолирован | Требует будущего программного обеспечения |
| Намерение и исполнение | YAML описывает план до запуска; JSON-карточка — факт после запуска | Граница явная |
| YAML и оболочка | YAML — переносимое хранение, не обязательный ручной интерфейс | Совместимо с будущей оболочкой |

## Найденные напряжения

1. Текущая карточка исполнения хранит `task`, `case` и `candidate` как ссылки с
   версиями, но не указывает контрольную сумму исходных YAML. При связывании
   форматов нужно решить, достаточно ли версии или требуется контрольная сумма.
2. Карточка допускает URI артефакта, а правила безопасного получения внешних
   входов ещё не определены. Поэтому URI пока не включён в черновик примера.
3. `data_policy` в задаче пока предложение. Его нельзя смешивать с фактическим
   сетевым ограничением исполнения.
4. Закрытые эталоны защищены пока только проектным правилом. До появления
   запускающего слоя нельзя утверждать, что изоляция технически обеспечена.

## Проверка на избыточность

Сейчас описаны только три сущности, которые уже обсуждены: задача, пример и
оценивание. Способ решения и эксперимент не специфицированы заранее. Ни одно
поле не объявлено универсальным без проверки на звуковом и документном
сценариях. Реализация форматов ещё не начата.

Следующая ревизия проводится после решения о видах входов примера или при
изменении одной из зафиксированных границ.
