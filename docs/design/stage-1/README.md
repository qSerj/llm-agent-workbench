# Проектирование первого этапа

Здесь формируется минимальный переносимый способ описать эксперимент до его
исполнения. Документы имеют статус черновиков: они фиксируют уже согласованные
решения, границы и открытые вопросы, но пока не являются реализованной схемой.

## Порядок чтения

1. [Рамки этапа](00-scope.md) — что проектируем сейчас и чего намеренно не касаемся.
2. [Задача](01-task.md) — общее намерение, входы, выходы и ограничения.
3. [Пример задачи](02-case.md) — конкретные входные данные и границы видимости.
4. [Оценивание](03-evaluation.md) — правила и данные для проверки результата.
5. [Способ решения](04-candidate.md) — команда или именованный переходник.
6. [Эксперимент](05-experiment.md) — человеческий вопрос и матрица исполнений.
7. [Контрольные сценарии](06-reference-scenarios.md) — звук и отчёт по документам.
8. [Открытые вопросы](07-open-questions.md) — решения, которые ещё не приняты.
9. [Ревизия согласованности](CONSISTENCY.md) — противоречия и связь с текущим ядром.

Удобное создание описаний через оболочку или языковую модель будет
специфицировано только после завершения минимального формата эксперимента.

## Статусы решений

- **Согласовано** — принято в обсуждении и используется далее.
- **Предложение** — рабочий вариант для проверки на сценариях.
- **Открытый вопрос** — решение намеренно отложено.

После существенного изменения любой спецификации обновляется `CONSISTENCY.md`.
