# ADR 0010: Парные серии агрегируются из карточек

Статус: принято и реализовано. Дата: 2026-08-31.

## Контекст

Карточка исполнения хранит один способ и один номер повтора. Оболочка умела
сравнивать отдельные исполнения, но не могла ответить на вопрос о серии из пяти
повторов: приходилось отдельным скриптом считать средние, медианы и отношения
русского варианта к английскому, а затем вручную объединять три эксперимента.

Из карточек нельзя надёжно вывести, какие способы образуют пару и какая сторона
должна быть числителем. Суффиксы `-ru` и `-en` относятся к одному исследованию и
не годятся как правило доменно-нейтральной лаборатории.

## Решение

1. Описание эксперимента может содержать `comparisons`. Каждое парное сравнение
   явно называет `numerator`, `denominator` и отображаемые метки сторон.
2. Определение пары остаётся намерением в `experiment.yaml`; карточка исполнения
   v1 не меняется. Фактические значения всегда читаются из карточек.
3. Стороны связываются только по одинаковому `repetition`. Для одной метрики
   считаются пары, в которых известны оба значения; их число показывается как
   `n` и не маскируется плановым количеством повторов.
4. Показываются четыре разных результата: среднее и медиана каждой стороны,
   отношение средних и медиана парных отношений. Нулевой знаменатель оставляет
   отношение неизвестным.
5. Состояния исполнения и каждый вид оценки агрегируются отдельно. Они не
   превращаются в единый балл.
6. `/series` объединяет выбранные сеансы нескольких экспериментов. Выбор живёт
   в GET-параметрах; без него берётся новейший сеанс каждого эксперимента с
   объявленными сравнениями.

## Следствия

Один расчётный модуль обслуживает оболочку и консольный анализатор. Языковой
опыт становится первым применением общего парного сравнения, а не особым режимом
ядра. Старые описания без `comparisons` и схема карточки v1 остаются совместимы.

Сохраняемый URL фиксирует выбранные сеансы, но не снимок намерения: если человек
изменит `comparisons` в текущем описании эксперимента, историческая сводка будет
прочитана через новое определение пары. Неизменяемый экспорт отчёта остаётся
отдельной будущей возможностью.

При реализации обнаружилась коллизия: разные сеансы могут законно содержать
одинаковый `execution_id`. Оболочка поэтому адресует карточку ключом из её пути
относительно `executions/`; старый идентификатор принимается лишь тогда, когда
он однозначен.
